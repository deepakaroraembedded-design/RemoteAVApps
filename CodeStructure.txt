VMC Thin Client — Complete Code Structure and File Details
================================================================================
Generated: 2026-09-08 (branch DEV0908)
Repo:      REMOTEAPPS/thin-client
Purpose:   MEC/edge low-latency DASH (LL-DASH) remote desktop / A/V playback.
           Server (vmc-dash-sim) muxes a 21-min clip to CMAF LL-DASH via
           NVENC; thin client (vmc-thinclient-app) demuxes + decodes (CUVID)
           and renders via DRM/KMS (shipping) or /dev/fb0, with ALSA audio.

Workload under test (agentic loop): ONE 21-minute clip played end-to-end in a
single stretch. Native 1920x1080@60fps H.264 + AAC 44.1kHz, 1260 s.

1. apps/thinclient/main.c  (4207 lines)  THE CLIENT
   ------------------------------------------------------------------
   Single-threaded-app wiring: reader thread + decode thread + present thread
   (DRM) / fb0 decode-worker present + audio thread + main loop.
   Important subsystems:
   - DASH reader: dash_reader_direct() — fetches MPD + CMAF segments, demuxes
     per-segment, publishes video AUs and decoded audio PCM. Anchors live edge
     to availabilityStartTime; clamps fetches to the manifest startNumber;
     play-once EOS detection + drain-before-exit (g_eos_reached /
     g_eos_end_wall_us).
   - Present pacing:
       * fb0: two-phase wait (hrtimer sleep + busy-spin on the audio-content
         crossing) — VMC_FB_PRESENT_SPIN_US; cadence floor
         max(deadline, last+period); audio-content gate.
       * DRM: present_worker() gates page flips on the LIVE audio-content
         crossing (tlm_audio_content_at_wall) with a fixed 2-vblank lead plus a
         constant sync-shift servo (s_sync_shift_us) that drives the measured
         av_offset to zero (mpv display_sync_error style).
   - Audio: audio_worker() renders clean 5ms periods; +2.33% AAC boundary-loss
     compensation applied at DELIVERY (audio_fifo_write_compensated), not in
     the render loop; ALSA position drives the audio-master clock.
   - A/V alignment telemetry: tlm_audio_content_at_wall / tlm_vrender_emit /
     tlm_arender_emit (NDJSON, env-gated VMC_TELEMETRY).
   - vsync_miss flagged only when late exceeds playout_latency + 1.5*frame.

2. tools/vmc-dash-sim/main.c  (942 lines)  THE DASH SERVER
   ------------------------------------------------------------------
   - Launches ffmpeg NVENC -> LL-DASH CMAF (streaming=1, SegmentTemplate,
     availabilityTimeComplete=false, --play-once => movie loop=1, MPD flips
     type="static" at EOS via patch_mpd_static()).
   - HTTP server: conn_handler() serves /live.mpd and /chunk-stream*-*.m4s.
   - serve_full() / serve_progressive() (chunked streaming of in-progress
     .tmp segments, tail-race fix sends remaining bytes after tmp->m4s rename).
   - Rollover deletion of old segments (rolling window).
   - srv telemetry: mpd_update, eos, hold_404, encoder_restart.

3. tools/av_harness/  THE MEASUREMENT HARNESS
   ------------------------------------------------------------------
   - env.sh: INPUT_CLIP, DASH_OUT, gates (GATE_AV_DRIFT_ABS_MS_PER_MIN=0.5,
     GATE_FRAME_INTERVAL_FRAC=0.10, GATE_AUDIO_PERIOD_TOLERANCE=0.005, ...),
     tiers (SMOKE 180s / FULL 1235s), CONTENT_FPS/AUDIO_RATE.
   - av_report.py: NDJSON -> 60s buckets -> per-bucket + run-level gates;
     builds buckets against the NOMINAL window, excludes EOS-drain artifacts
     after the eos event, playback_span = content reached (max frame pts).
   - relaunch.sh: clean slate, VMC_DRM, kill-verify-purge-start-verify.
   - collect.sh: precheck, warm-up 15s, measured window, 30s heartbeat,
     resource samples, EOS capture.
   - selftest_synth.py: 22 injected-fault scenarios; gate/localisation checks.

4. src/video/drm_scanout.c  (312 lines)  DRM/KMS
   ------------------------------------------------------------------
   - drmModeSetCrtc modeset, dumb-buffer alloc/import (DMA-BUF prime_fd),
     page flips (drmModePageFlip), single-pass drain_events (returns at the
     first flip event — the iter-005 phase-lock fix), vblank-period estimate.

5. src/video/ffmpeg_decoder.c  (374 lines)  CUVID decode
   ------------------------------------------------------------------
   - av_hwdevice_ctx_create + get_format callback (h264_cuvid), frame reorder
     by PTS, swscale/NV12->BGRA conversion, output stride/pitch.

6. tools/cuda/nv12_conv.cu  (249 lines)  GPU conversion kernel
   ------------------------------------------------------------------
   - libnv12conv.so: async NV12->BGRA kernel (conv_async/conv_stage/conv_wait),
     cudaSetDevice(0) before use.
